Pourquoi WebSearch Agent ?

Les moteurs de recherche classiques retournent des liens. Les LLM seuls sont limites a leur date d'entrainement. WebSearch Agent combine les deux : il cherche en temps reel, analyse les sources, et synthetise une reponse complete avec citations.

❌ LLM classique
  • Pas d'acces a l'information en temps reel
  • Connaissances datees (cutoff d'entrainement)
  • Pas de sources, pas de citations
  • Hallucinations possibles
✅ WebSearch Agent
  • Recherche en temps reel via 13 sources
  • Informations a jour et verifiees
  • Citations avec URLs sources
  • Verification croisee des donnees

Comment ca marche

Le flux complet en 5 etapes :

1. Requete
Question en naturel
2. Routage
Detection intention + complexite
3. Recherche
Execution parallele des outils
4. Synthese

Texte + citations sources

Features principales

Recherche intelligente

Routage automatique par intention, domaine et complexite. Selection optimale des sources.

Execution parallele

Jusqu'a 6 outils executes en parallele. Cache LRU pour les requetes frequentes.

Securite enterprise

OAuth2 JWT, scopes, rate limiting, 2FA, headers de securite. Pret pour la production.

Observabilite totale

Metrics en temps reel, logs structures, circuit breaker, monitoring par source.

Authentication & OAuth2

3 modes d'authentification supportes. OAuth2 recommande pour la production.

Vue d'ensemble

🔑 API Key

Simple et rapide. Pas de token a gerer.

✓ Aucune configuration
✗ Pas de scopes
✗ Pas de refresh
🛡️ OAuth2 JWT

Recommande. Scopes, refresh, expiration.

✓ Scopes (read/write/admin)
✓ Refresh token
✓ Rate limit par client
🌐 Sans credentials

Development uniquement.

✓ Aucune config
✗ Rate limit strict (IP)
✗ Pas de tracking

Mode 1 : API Key

La methode la plus simple. Utilisez votre api_key (format ws_...).

Utilisation

# Via header X-API-Key
curl -H "X-API-Key: ws_votre_api_key" \
  http://localhost:4500/chat \
  -d '{"message": "Bonjour"}'

# Via Authorization Bearer
curl -H "Authorization: Bearer ws_votre_api_key" \

  -d '{"message": "Bonjour"}'

Mode 2 : OAuth2 JWT (recommande)

Flow complet avec tokens temporaires, scopes, et refresh.

Etape 1 : Creer un client

Allez dans Admin → Apps et cliquez "Ajouter une app".

Important

Copiez le client_id et le client_secret — ils ne seront plus visibles apres la creation.

Etape 2 : Obtenir un token

POST /oauth/token 
curl -X POST http://localhost:4500/oauth/token \
  -H "Content-Type: application/json" \
  -d '{
    "client_id": "VOTRE_CLIENT_ID",
    "client_secret": "VOTRE_CLIENT_SECRET"
  }'

Reponse :

{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "client_id": "2da1db9a-...",
  "scopes": ["read", "write"]
}

Etape 3 : Utiliser le token

curl -X POST http://localhost:4500/chat \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIs..." \
  -d '{"message": "Qu\'est-ce que le W3C ?"}'

Etape 4 : Refresh token

Les tokens expirent apres 1 heure. Utilisez le refresh endpoint :

POST /oauth/token/refresh 
curl -X POST http://localhost:4500/oauth/token/refresh \
  -H "Content-Type: application/json" \
  -d '{"refresh_token": "eyJhbGciOiJIUzI1NiIs..."}'
Grace period

Le refresh fonctionne pendant 15 minutes apres l'expiration du token. Pass ce delai, il faut se re-authentifier.

Scopes & Permissions

Les scopes controlent l'acces aux endpoints. Ils sont verifies automatiquement.

ScopeDescriptionEndpointsExemple
readLire et rechercher/search, /threads, /datasetsApp mobile en lecture seule
writeEnvoyer des messages/chatChatbot, assistant IA
adminGerer l'administration/admin/*Dashboard admin

Scopes par defaut

Nouveau client → ["read", "write"]

Modifier les scopes

# Via l'API admin
curl -X PUT http://localhost:4500/admin/clients/{id}/scopes \
  -H "Content-Type: application/json" \
  -H "Cookie: session=..." \
  -d '{"scopes": ["read", "write", "admin"]}'

Erreur 403

{
  "detail": "Scope 'write' requis. Scopes disponibles: read"
}

Erreurs courantes

CodeErreurCauseSolution
401Non authentifieCredentials manquants ou invalidesVerifier client_id/secret ou API key
403Scope insuffisantLe scope demande n'est pas dans le tokenModifier les scopes du client
429Rate limitTrop de requetesAttendre ou augmenter la limite

Bonnes pratiques

✓ Faire
  • Utiliser OAuth2 en production
  • Stocker les secrets dans .env
  • Refresh avant expiration
  • Scopes minimum necessaires
✗ Ne pas faire
  • Coder les secrets dans le source
  • Utiliser sans credentials en prod
  • Donner le scope admin a tout le monde
  • Partager les tokens

Classe OAuth2

import requests

class WebSearchClient:
    def __init__(self, client_id, client_secret):
        self.client_id = client_id
        self.client_secret = client_secret
        self.token = None

    def login(self):
        resp = requests.post(
            'http://localhost:4500/oauth/token',
            json={
                'client_id': self.client_id,
                'client_secret': self.client_secret
            }
        )
        self.token = resp.json()['access_token']

    def search(self, query):
        return requests.post(
            'http://localhost:4500/chat',
            json={'message': query},
            headers={'Authorization': f'Bearer {self.token}'}
        ).json()

# Utilisation
client = WebSearchClient('id', 'secret')
client.login()
result = client.search('python')
print(result['response'])
